# Кнопки сервисов на своём профиле (две линии)

**Статус:** продуктовый UI-паттерн (зафиксировать до вёрстки)  
**Где:** свой профиль — блок быстрых входов в сервисы (не чужой профиль, не нижний бар)  
**Связано с:** [tag-powers.md](../business/tag-powers.md) · [booking-staff-plan.md](../business/booking-staff-plan.md) · [profile.md](../business/profile.md) · [adaptive-widgets.md](adaptive-widgets.md)

Мобилка и сайт — **один** паттерн.

---

## Зачем

Сервисов станет больше (запись, посещаемость…). Если каждую силу рисовать крупной кнопкой с текстом — **забьёт профиль**.  
Поэтому: две тонкие линии + плотность по числу кнопок в линии.

---

## Две линии

```
┌─────────────────────────────────────┐
│  шапка профиля / edit / settings…   │
├─────────────────────────────────────┤
│  ВЕРХНЯЯ линия — силы «работника»   │  ← теги вроде bookingCalendar
│  [ … ] [ … ]                        │
├─────────────────────────────────────┤
│  НИЖНЯЯ линия — силы «админа»       │  ← теги вроде booking
│  [ … ] [ … ]                        │
├─────────────────────────────────────┤
│  посты / кластеры…                  │
└─────────────────────────────────────┘
```

| Линия | Определение тегов | Примеры |
|-------|-------------------|----------|
| **Верхняя** | `worker` | `bookingCalendar` → календарь заказов, которые мне дают |
| **Нижняя** | `admin` | `booking` → приём записи / inbox |

Это **не иерархия аккаунтов**, а раскладка по **определению силы** ([tag-powers.md](../business/tag-powers.md)): worker сверху, admin снизу.  
Пустая линия **не рисуется** (нет ни одной кнопки в ряду → ряд скрыт).

Клиентский вход «Мои бронирования» (куда мне идти) — **не** в этих двух линиях; он остаётся в ⋯ / меню (см. [booking-staff-plan.md](../business/booking-staff-plan.md)).

---

## Плотность в линии (обязательное правило)

Считаем кнопки **в одной линии** (верх и низ — независимо).

| Число кнопок в линии | Как выглядит каждая |
|----------------------|---------------------|
| **1 или 2** | **Иконка + текст** (подпись силы / сервиса) |
| **3 и больше** | **Только иконка** (текст не ставить — иначе забьёт ряд) |

```
1–2 в линии:   [ 📅 Календарь ]  [ … другой ]

3+ в линии:    [ 📅 ] [ 🕐 ] [ 📍 ] [ … ]
```

Подсказка при тапе (tooltip / long-press / `title`) — желательна, когда осталась только иконка.

Порог **строго по линии**: сверху две кнопки с текстом, снизу три — только иконки внизу; верх при этом может остаться с текстом.

---

## Показ кнопки

- Кнопка появляется только если у пользователя есть **соответствующая сила тега** ([tag-powers.md](../business/tag-powers.md)).
- Нет тега → нет кнопки → линия может исчезнуть целиком.
- Порядок внутри линии — стабильный (каталог сервисов / порядок сил), не прыгает от сессии к сессии.

---

## При вёрстке (чеклист агента)

- [x] Два ряда: worker сверху, admin снизу — не одна каша кнопок
- [x] Пустой ряд не занимает место
- [x] `count <= 2` → icon + label; `count >= 3` → icon only (на эту линию)
- [x] Паритет Flutter + web
- [x] Не класть сюда «Мои бронирования» клиента
- [x] Ресурсы: иконки из `AppIcons` / веб-токенов сервиса; без сырых `Icons.*` / hex в фиче

---

## Коротко

```
Верх = worker (определение тегов)
Низ  = admin (определение тегов)
≤2 в ряду → иконка + текст
≥3 в ряду → только иконка
Пустой ряд не рисуем. Мобилка = сайт.
```
