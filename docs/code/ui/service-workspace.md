# Рабочий стол сервиса (сайт)

**Для кого:** UI сайта — Запись, Посещаемость, Ресурсы, Бронь.  
**Продукт:** [website-host-desktop.md](../../business/website-host-desktop.md).  
**Кэш:** [website-service-cache.md](../../business/website-service-cache.md).

Каркас rail — `ServiceWorkspaceShell`. Тело экрана — одни и те же слоты, акцент только цветом сервиса.

## Слоты

| Слот | Компонент | Когда |
|------|-----------|--------|
| Лид | `lead` на shell | Всегда: одно предложение, что на экране |
| Информер | `ServiceInformer` | Факт или следующий шаг; ошибка — `tone="warning"` |
| Секция | `ServiceSection` | Группа: лейбл и/или заголовок + действие |
| Тайл | `ServiceTile` | Переход: куда и что внутри |
| Пусто | `ServiceEmpty` | Нет данных + одно действие |
| Загрузка списка | `ServiceListShimmer` | Первый заход без кэша; не «Загрузка…» текстом |
| Подтверждение | `ServiceConfirmDialog` | Удалить / убрать — только после модалки |

Файлы: `web/src/features/shared/components/service-page.tsx`, shell — `service-workspace-shell.tsx`.

## Текст

- Тайтл совпадает с пунктом nav. Без английских ярлыков в UI («Inbox», «CRM»).
- Лид — одно предложение.
- Подпись тайла — что пользователь найдёт внутри, не внутреннее имя экрана.
- Информер не дублирует лид.

## Данные

Экран читает один метод фичи. Повторный заход на ту же сущность (Обзор и день Записи) делит `coalesceAsync` + localStorage SWR (`runServiceSwr`). Поиск не пишет кэш.
