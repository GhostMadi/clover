# Фильтры ленты, карты и профиля

**Статус:** актуально на сейчас  
**Связано с:** [navigation-bars.md](navigation-bars.md), [publications.md](publications.md), [profile.md](profile.md), [settings.md](settings.md)

---

## Зачем

Пользователь сужает контент под задачу: **городская лента и карта** — по месту, датам, тегам; **свой профиль** — по своим категориям фильтров для витрины.

Это **две разные системы**, не один общий «фильтр приложения».

---

## 1. Фильтр Home (Event / Map)

### Точка входа

Home → **иконка фильтра слева** от нижнего бара ([navigation-bars.md](navigation-bars.md)).

Отдельные состояния для **ленты** и **карты**: переключение Event ↔ Map не сбрасывает фильтр другого режима.

### Лента (Event)

| Поле | Смысл |
|------|--------|
| **Страна / город** | География ленты (ключи справочника, подписи на клиенте) |
| **Содержимое** | **«Все»** (посты + ивенты) или **«Ивенты»** (только с маркером) |
| **Период** | Даты ивента (видны, если не «Все») |
| **Эмодзи** | Фильтр по эмодзи поста |
| **Теги** | Маркерные теги (`salon`, `food`, …) |

По умолчанию лента — **«Все»** для выбранного города.

### Карта (Map)

Те же **страна, город, период, эмодзи, теги**.  
На карте **всегда только ивенты** — переключателя «Все / Ивенты» нет.

### Шаги

1. Тап по фильтру → шторка параметров.
2. Выбор значений → **Применить**.
3. Лента / карта перезагружаются с новым набором.

### Правила

- Справочники стран/городов — enum + catalog на клиенте, на бэк уходят **ключи**.
- При режиме ленты **«Все»** фильтры, специфичные для ивента (даты, эмодзи, теги), **скрыты** — они не имеют смысла для обычных постов.
- Точка на иконке фильтра: активна, если выбрано что-то кроме «дефолта» (для ленты «Все» считается базовым режимом).
- **Карта (нагрузка + динамика):** маркеры подгружаются по viewport одним RPC; повторный запрос — только если камера ушла ≥ ~40% радиуса или zoom заметно изменился (мобилка и сайт одинаково). Мелкий pan не бьёт бэк; фильтр / «моя гео» — force reload. **Дисковый кэш** ячейки viewport (stale-while-revalidate, TTL ~6ч): сразу показать снимок → обновить с сети.

### Ограничения (как сейчас)

- Полное состояние фильтра **не сохраняется** между перезапусками приложения (кроме частичного чтения страны/города при старте — без записи при «Применить»).
- Фильтр Home **не связан** с категориями фильтров профиля.

## 2. Фильтры витрины профиля (свои категории)

### Точка входа

- **Настройки → Ресурсы → Фильтры** — создать категории и значения.
- **Свой профиль** — строка чипов над сеткой постов.
- **Создание поста** — привязать пост к значениям фильтров.

### Шаги (хозяин витрины)

1. В настройках создаёт категорию (например «Услуга») и значения («Стрижка», «Окрашивание»).
2. На профиле выбирает чипы → сетка показывает только посты с этими метками.
3. При публикации отмечает, к каким значениям относится пост.

### Правила

- Категории и значения **личные** — у каждого автора свой набор.
- Ключ значения в UI: `category_id:label` (внутренняя модель).
- Гость на чужом профиле видит чипы, если автор их включил на витрине.

---

## Вне скоупа (пока)

- Единый «глобальный» фильтр на всё приложение.
- Фильтр ленты по **сохранённым локациям** пользователя (локации — только для постов, см. [locations.md](locations.md)).
- Синхронизация фильтра Home между устройствами.
