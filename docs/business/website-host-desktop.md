## Зачем

Сайт Clover — **панель хозяина** на широком экране: день, штат, услуги, локации.  
Мобилка — поле (punch / GPS) и клиент «на ходу».

## Участники / роли

| Роль | Где |
|------|-----|
| Начальник (теги `booking` / `attendance` / `resources`) | Сайт: workspace сервиса |
| Работник (`attendanceWork`) | Punch в приложении; на сайте — read-only |
| Клиент записи | `/u/…/book`, «Мои бронирования» — узкий shell |

## Одна структура UI

Все три сервиса — один каркас `ServiceWorkspaceShell`:

```
md+:
┌──────── rail 240px ──┬────── контент ──────────┐
│ Бренд сервиса        │ Заголовок экрана  [CTA] │
│ Entity (точка/комп.) │─────────────────────────│
│ Nav · день / работа  │ children                │
│ ─── Ещё ───          │                         │
│ Настройки / гайд     │                         │
└──────────────────────┴─────────────────────────┘

mobile: назад + title + entity · чипы nav · контент
```

| Слот | Смысл |
|------|--------|
| Бренд | Запись / Посещаемость / Ресурсы |
| Entity | Селектор точки или компании (Ресурсам не нужен) |
| Nav `main` | День + ежедневная работа |
| Nav `more` | Точки/компании, гайд, настройки |
| Trailing | Только CTA экрана (`+`, сохранить…) |

| Сервис | Entity | День (`main` первый) | Ещё |
|--------|--------|----------------------|-----|
| Запись | Точка | Записи (inbox) | Настройки, точки |
| Посещаемость | Компания | Сегодня | Настройки, компании |
| Ресурсы | — | Обзор | — |

Гайд Записи / Посещаемости / Ресурсов — **тайл на обзоре**, не пункт rail; тап → коротко про функции сервиса.

**Настройки Записи** — хаб в «Ещё» для **выбранной точки** (как Настройки компании в посещаемости).

Клиент («Мои бронирования») — **не** в host-nav: вход с профиля / настроек (как мобилка: Profile → ⋯).

**День хозяина:** master–detail на `lg:` (список | инспектор), без лишних полных переходов.
