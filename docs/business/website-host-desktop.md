## Зачем

Сайт Clover — **панель хозяина** на широком экране: день, штат, услуги, локации.  
Мобилка — поле (punch / GPS) и клиент «на ходу».

## Участники / роли

| Роль | Где |
|------|-----|
| Начальник (теги `booking` / `attendance` / `resources`) | Сайт: workspace сервиса |
| Работник (`attendanceWork`) | Punch в приложении; на сайте — read-only |
| Клиент записи | `/u/…/book`, «Мои бронирования» — узкий shell |

## Одна структура UI

Все три сервиса — один каркас `ServiceWorkspaceShell`:

```
md+:
┌──────── rail 240px ──┬────── контент ──────────┐
│ Бренд сервиса        │ Заголовок экрана  [CTA] │
│ Entity (точка/комп.) │─────────────────────────│
│ Nav · день / работа  │ children                │
│ ─── Ещё ───          │                         │
│ Настройки / гайд     │                         │
└──────────────────────┴─────────────────────────┘

mobile: назад + title + entity · чипы nav · контент
```

| Слот | Смысл |
|------|--------|
| Бренд | Запись / Посещаемость / Ресурсы |
| Entity | Селектор точки или компании (Ресурсам не нужен) |
| Nav `main` | День + ежедневная работа |
| Nav `more` | Точки/компании, гайд, настройки |
| Trailing | Только CTA экрана (`+`, сохранить…) |

| Сервис | Entity | День (`main` первый) | Ещё |
|--------|--------|----------------------|-----|
| Запись | Точка | Обзор, записи, услуги, аналитика, настройки, гайд, чат, точки — все в rail | — |
| Посещаемость | Компания | Сегодня, люди, дежурства, табель, зарплата, аналитика, настройки, гайд, чат, компании — все в rail | — |
| Ресурсы | — | Обзор, местоположения, фильтры, гайд — все в rail | — |

Гайд у всех трёх сервисов — пункт rail. Обзор — сводка (что уже есть и что пусто), не второе меню из тайлов.

Необратимое действие (удалить место, фильтр, убрать мастера или человека) — только через модалку подтверждения (`ServiceConfirmDialog`), не сразу по кнопке и не через `confirm()` браузера.

**Чат точки и чат компании** раскрываются в колонке контента рабочего стола. Раздел «Чаты» кабинета при этом не открывается.

**Настройки Записи** — хаб в «Ещё» для **выбранной точки** (как Настройки компании в посещаемости).

Клиент («Мои бронирования») — **не** в host-nav: вход с профиля / настроек (как мобилка: Profile → ⋯).

**День хозяина:** master–detail на `lg:` (список | инспектор), без лишних полных переходов.

## Тело экрана (все сервисы)

Rail и шапка общие. Внутри контента — одна анатомия, не свой набор карточек на каждый сервис:

```
шапка: сервис · тайтл · [CTA]
тело:
  лид      — одно предложение: что это за экран
  информер — опционально: факт или следующий шаг
  секция   — заголовок + контент
  тайл     — куда идти и что внутри
  пусто    — что пусто и какое действие
```

| Слот | Правило текста |
|------|----------------|
| Тайтл | Русская фраза из nav («Записи», не «Inbox») |
| Лид | Одно предложение без жаргона |
| Тайл | Куда + что внутри одной строкой |
| Информер | Факт или следующий шаг, не декоративный баннер |

Компоненты: `ServicePageLead`, `ServiceInformer`, `ServiceSection`, `ServiceTile`, `ServiceEmpty` в `web/src/features/shared/components/`. Акцент — цвет сервиса, не отдельный layout.
