# Онлайн-запись (как сейчас)

**Статус:** актуально на сейчас  
**Для кого:** продукт / бизнес / дизайн  
**Не про:** SQL, RPC, cubit’ы  

Техника (бэк): [SPEC_BOOKING_SYSTEM.md](../supabase/SPEC_BOOKING_SYSTEM.md)  
Профиль и точки входа: [profile.md](profile.md) · теги: [profile-data.md](profile-data.md)

---

## Цель

**Запись** — клиент выбирает услугу, время и мастера у хозяина профиля; запись **сразу подтверждена**; хозяин **ведёт визит** до завершения.

Один аккаунт Clover может быть **и клиентом, и хозяином записи** — это разные роли, не два типа регистрации.

---

## Главное правило: нет отдельного «бизнес-аккаунта»

| Что думает пользователь | Как устроено в Clover |
|-------------------------|------------------------|
| «Бизнес-аккаунт» | Обычный профиль + теги (`business`, `salon`, …) — **кто вы** |
| «Принимаю запись» | Тег **`booking`** в профиле — **включена функция записи** |
| «Обычный пользователь» | Любой аккаунт; может записываться к другим через **Мои бронирования** |

Тег **`business`** (группа `who`) ≠ включение записи.  
Запись включается только тегом **`booking`** (группа `account`).

---

## Роли

| Роль | Кто это | Что делает |
|------|---------|------------|
| **Клиент** | Любой авторизованный пользователь | Записывается с чужого профиля; смотрит **Мои бронирования**; отменяет свою запись до начала визита |
| **Хозяин (host)** | Владелец профиля с тегом `booking` | Настраивает услуги и расписание; ведёт визит в inbox; смотрит аналитику |
| **Исполнитель (staff)** | Мастер внутри аккаунта хозяина | Привязан к услугам; клиент выбирает при записи; может быть с аккаунтом Clover или только по имени |

Хозяин **не может записаться к самому себе**.

---

## Два сценария одним взглядом

```
Обычный аккаунт (как клиент)
  └── чужой профиль (у хозяина есть booking)
        └── Записаться → услуга → мастер → дата/слот → подтвердить
  └── пост хозяина с услугой
        └── Записаться на эту услугу → тот же flow, услуга уже выбрана
  └── Profile → ⋯ → Мои бронирования

Аккаунт с приёмом записи (как хозяин)
  └── Редактировать профиль → тег booking
  └── Настройки → Запись → услуги, расписание, inbox, аналитика
  └── Настройки → Запись → Услуги — бонусы на каждой услуге (см. [bonuses.md](bonuses.md))
  └── может также быть клиентом у других (⋯ → Мои бронирования)
```

## Точки входа

| Откуда | Куда | Для кого |
|--------|------|----------|
| Чужой профиль → **Записаться** | Экран записи к этому хозяину (выбор услуги) | Клиент |
| Пост с привязанной услугой → **Записаться на эту услугу** | Тот же экран записи; услуга **уже выбрана** | Клиент |
| Profile → **⋯** → **Мои бронирования** | Список своих записей | Клиент |
| Свой профиль → **⚙ Настройки** → **Запись** | Inbox «Мои записи», услуги, аналитика | Хозяин |
| Inbox → **Услуги** | Каталог услуг хозяина | Хозяин |
| Inbox → **⚙** (на экране услуг) | Расписание, выходные, отсутствия | Хозяин |
| **Запись → Услуги** | Бонусы: начисление и % списания на услуге | Хозяин |

На **витрине профиля** нет прайса и списка услуг — только кнопка «Записаться» у гостя.  
Пост может быть витриной **одной** услуги (см. ниже).

См. [навигацию](navigation-bars.md): ⋯ у вкладки Profile.

## Хозяин: включение и настройка

### 1. Включить приём записи

1. Свой профиль → **Редактировать**.
2. В **тегах аккаунта** добавить **`booking`** («принимаю запись»).
3. Сохранить.

Без этого тега кнопки «Записаться» на профиле нет и создать запись к этому человеку нельзя.

### 2. Услуги

**Настройки → Запись → Услуги** (или кнопка «Услуги» в inbox).

Для каждой услуги:

- название, emoji, длительность, цена;
- описание (по желанию);
- буфер после визита, макс. участников;
- **исполнители** — один или несколько мастеров (поиск аккаунта Clover или имя);
- **бонусы** — начисление и % списания на услуге — [bonuses.md](bonuses.md).

Деактивировать услугу нельзя, пока есть **будущие** активные записи на неё.

### 3. Расписание

**Услуги → ⚙ Настройки записи**:

- выходные дни недели;
- **горизонт записи**: на N дней вперёд (7–90) или до конкретной даты;
- общие рабочие часы (с / до);
- **отсутствия исполнителей** (диапазон дат + заметка).

Слоты для клиента считаются **на сервере** с учётом расписания, занятости мастера, блокировок и пересечений с другими записями клиента.

### 4. Бонусы (на услуге)

Поля **«Бонусов за визит»** и **«Оплата бонусами (%)»** — в форме каждой услуги. Отдельного экрана «Бонусы» в настройках нет.  
Подробно: [bonuses.md](bonuses.md).

## Клиент: запись к хозяину

### Условия

- Вы авторизованы.
- Открыт **чужой** профиль **или** чужой пост с активной услугой.
- У хозяина есть тег **`booking`**.
- Вы **не** хозяин этого профиля.

### Шаги (с профиля)

1. На чужом профиле нажать **Записаться**.
2. Выбрать **услугу**.
3. Выбрать **мастера** (если один — подставляется сам).
4. Выбрать **дату** (в пределах горизонта хозяина).
5. Выбрать **слот времени** из доступных.
   - Недоступные слоты не показываются или помечены (занято, выходной, отсутствие мастера).
   - Учитываются **ваши** записи у других хозяев — пересечение по времени запрещено.
6. По желанию — **комментарий** к записи.
7. Если у услуги разрешена оплата бонусами и есть баланс — переключатель **«Оплатить бонусами»**.
8. Проверить сводку → **Записаться**.

### С поста (шорткат)

1. На чужом посте с привязанной **активной** услугой нажать **«Записаться на эту услугу»**.
2. Дальше — те же шаги, начиная с **мастера** (услуга уже выбрана).

На **своём** посте кнопки записи нет.

**Результат:** запись сразу **«Подтверждена»** (целевое поведение; см. [продуктовые решения](#продуктовые-решения)). Слот занят; хозяин видит запись во **«Предстоящих»**, не в «Надо подтвердить».

## Хозяин: не CRM, а операционный минимум

Clover **не копирует** salon-CRM (Zapis Partner и аналоги): нет склада, зарплат, отдельной базы телефонов, кассы.

**Что нужно хозяину — уже в продукте:**

| Задача | Где |
|--------|-----|
| Каталог услуг (название, **цена**, длительность, мастера) | **Услуги** |
| Расписание, горизонт, отсутствия | **Настройки записи** |
| Журнал на сегодня / неделю, статусы визита | **Inbox «Мои записи»** |
| Сводка за период | **Аналитика** |
| Лояльность | **Запись → Услуги** (поля бонусов) · **⋯ → Мои бонусы** (клиент) |

Клиент уже **аккаунт Clover** — отдельная «картотека клиентов» не нужна; история = `bookings` + профиль.

### Аналитика (вместо тяжёлой CRM-отчётности)

**Inbox → Аналитика** — единственный экран «цифр» для хозяина.

**Уже считает бэк** (`get_booking_analytics`), часть **ещё не на UI**:

| Метрика | На экране сейчас | Можно добавить в аналитику |
|---------|-------------------|----------------------------|
| Всего записей за период | ✅ | — |
| Популярные услуги | ✅ | — |
| Фильтр по исполнителю | ✅ | — |
| Выручка (завершённые визиты) | ✅ | — |
| Средний чек | ✅ | — |
| Разбивка по статусам | ✅ | — |
| Топ мастеров (записи, выручка) | ✅ | — |
| No-show, отмены клиентом vs хозяином | нет | 🔜 при необходимости |
| Заполняемость слотов (%) | нет | 🔜 если понадобится |

Правило: **новые «CRM-метрики» — только через аналитику**, не отдельным продуктом.

## Цена и оплата

- **Прайс на витрине профиля нет** — и не нужен отдельный каталог на шапке.
- **Цена задаётся на услуге**; клиент видит её при выборе услуги в flow «Записаться».
- В **сводке перед записью** и в **«Мои бронирования»** — цена из **снапшота** на момент записи (если прайс потом изменится, старые записи не пересчитываются).
- **Оплата картой в приложении** — не v1; бонусы (списание/начисление) — см. ниже.
- **Услуга ↔ пост:** хозяин с тегом `booking` может привязать **одну активную услугу** при создании публикации. Гость видит CTA «Записаться на эту услугу» — тот же flow, услуга предвыбрана. На своём посте CTA нет. Сменить услугу после публикации — пока нет. Подробнее: [publications.md](publications.md).

## Продуктовые решения

| Тема | Решение |
|------|---------|
| CRM как у Zapis | **Не делаем** — inbox + услуги + аналитика |
| Прайс | **На услуге**; на профиле отдельного прайса нет |
| Услуга ↔ пост | **Есть:** привязка при создании (если `booking`); CTA у гостя = тот же flow с предвыбранной услугой. Смена после публикации — нет |
| Создание записи | **Мгновенно «Подтверждена»** (`create_booking` → `confirmed`) |
| Push на телефон | Позже; **in-app** — создание, отмена, **напоминания** (24 ч / 3 ч / 1 ч / 30 мин) — [notifications.md](notifications.md) |
| Отзывы | **Отдельно** от flow записи; блок в аккаунте / профиле позже |
| Маркетплейс / SEO | **Не цель** — discovery через профиль, ленту, карту, подписки |

## Клиент: мои бронирования

**Profile → ⋯ → Мои бронирования**

- Список записей; **календарь** для выбора дня.
- Карточка → детали: хозяин, услуга, время, статус, **цена** (из снапшота).
- **Отмена:** для активных записей до начала визита → **«Отменена»**.

---

## Хозяин: inbox «Мои записи»

**Настройки → Запись**

Верхняя панель: **Услуги** · **Аналитика**. Период и день — через **календарь** на экране.

### Вкладки

| Вкладка | Что внутри | Основные действия |
|---------|------------|-------------------|
| **Сейчас в кресле** | Текущий визит | Карточка «сейчас», профиль клиента, шаги визита |
| **Предстоящие** | Будущие записи (**основной поток**; сразу `confirmed` после онлайн-записи) | Просмотр, детали |
| **Прошедшие и архив** | Незакрытые прошедшие, история, отмены | «Был» / «Не пришёл»; детали |

Legacy `pending` (если остались в БД) показываются во **«Предстоящих»** с чипом «Ожидает»; отдельной вкладки «Надо подтвердить» нет.

Сверху — **календарь** (точки на днях с активными записями); тап по дню фильтрует «Предстоящие».

По умолчанию при открытии — период **«Все записи»**, вкладка **«Предстоящие»**.

### Деталь записи (хозяин)

- Клиент, услуга, мастер, время, заметка, **цена**.
- **Прогресс визита:** Подтверждена → Клиент пришёл → Оказывается → Оказана.
- **Откат** последнего шага (если ошиблись).
- Меню **⋯:** завершить, отменить, «не пришёл».

## Статусы записи

| Статус | Для пользователя | Кто обычно меняет |
|--------|------------------|-------------------|
| **Ожидает** | Заявка (legacy / опция «ручное подтверждение») | Не целевой happy path |
| **Подтверждена** | Запись создана | **Сразу при онлайн-записи** (целевое) |
| **Клиент пришёл** | Клиент на месте | Хозяин на визите |
| **Оказывается** | Услуга идёт | Хозяин |
| **Оказана** | Визит завершён | Хозяин / архив «Был» |
| **Отменена** | Запись снята | Хозяин отклонил; клиент отменил; экстренная отмена |
| **Не пришёл** | Клиент не явился | Хозяин / архив |

**Финальные статусы:** Оказана, Отменена, Не пришёл — дальше не меняются.

Если время визита прошло, а хозяин не закрыл визит — в архиве может отображаться как **«требует закрытия»** (подтверждена / клиент пришёл / оказывается после end time).

## Бонусы и запись

| Этап | Что происходит |
|------|----------------|
| Настройка | Хозяин: поля бонусов **на услуге** — см. [bonuses.md](bonuses.md) |
| Запись | Клиент может включить списание бонусами (если услуга и баланс позволяют) |
| После визита «Оказана» | Сервер списывает / начисляет бонусы по правилам, зафиксированным в записи |

Клиент смотрит баланс: **Profile → ⋯ → Мои бонусы**.

## Сравнение: обычный аккаунт vs хозяин записи

| | Обычный пользователь (только клиент) | Хозяин с записью |
|--|--------------------------------------|------------------|
| Тег `booking` | Нет | **Да** — обязательно |
| Кнопка «Записаться» на своём профиле | Нет | Нет (к себе нельзя) |
| Запись к другим | Да | Да |
| **Мои бронирования** (⋯) | Да | Да |
| **Настройки → Запись** | Inbox пуст / нет услуг | Услуги, inbox, аналитика |
| Витрина профиля | Посты, кластеры | То же; **прайс-лист на шапке** не нужен (цена на услуге); пост может вести на **одну** услугу |

Один человек может завести салон: добавить `business` + `booking`, настроить услуги — и при этом записываться к другому мастеру как клиент.

| Есть | Нет (пока) |
|------|------------|
| «Записаться» на **чужом** профиле с `booking` | Каталог услуг на витрине (цена — **в flow услуги**) |
| **Мои бронирования** через ⋯ | Управление inbox с самой витрины |
| **Запись** в Настройках | Отдельный тип аккаунта «Business» |
| Тег `booking` в редактировании профиля | Push на телефон (in-app — [notifications.md](notifications.md)) |

## Уведомления по записи

In-app уведомления по записи живут в **общей ленте** (колокольчик Home), не отдельным экраном.  
Полный процесс (соц + запись, бейдж, тексты на клиенте): **[notifications.md](notifications.md)**.  
Техника: [SPEC_IN_APP_NOTIFICATIONS.md](../supabase/SPEC_IN_APP_NOTIFICATIONS.md) § Booking.

Кратко для записи: instant booking → нет «хозяин одобрил»; хозяину — новая запись, визит, закрытие; клиенту — подтверждение, **напоминания за 24 ч / 3 ч / 1 ч / 30 мин**, отмена, итог визита (+ бонусы после «Оказана»).

---

## Ограничения и правила

- **Один слот — один мастер:** двойная запись на одно время исключена на бэке.
- **Клиент не может** иметь две активные записи на пересекающееся время (даже у разных хозяев).
- **Самозапись** запрещена.
- **Слоты** только из доступных сервером; клиент не вводит время вручную.
- **Перенос записи** на бэке заложен; отдельного UI переноса пока нет.
- **Отзывы** после визита — схема есть, UI позже.
