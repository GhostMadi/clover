**Статус:** процесс COP · **mock UI** web + mobile (полный guest flow) · бэка нет

## 1. Смысл и границы

**Зачем:** гость в барбершопе / салоне видит план зала, тапает кресло (emoji), сразу получает услугу + мастера, выбирает дату/слот и записывается — **тот же** `create_booking`, что и без схемы.

**Чем не является:**

| Не это | Почему |
|--------|--------|
| Второй каталог услуг | Услуга одна; схема только указывает на неё |
| Inventory столов как в Брони | У Записи занятость = слоты мастера, не «кресло занято навсегда» |
| Редактор геометрии | Рисуют в Ресурсах; здесь только bind и витрина |
| Обязательный путь | Без схемы / без bind — классика: услуга → мастер → слот |

---

## 2. Роли и сущности

| Роль | Кто | Делает |
|------|-----|--------|
| **Хозяин точки** | Профиль с `booking` + точка | Вешает схему на точку; bind emoji → услуга (± мастер) |
| **Мастер (staff)** | Исполнитель услуги | Может быть указан на emoji; слоты — его |
| **Гость (клиент)** | Любой авторизованный | Схема **или** список услуг → дата → слот → «Записаться» |
| **Без точки / без схемы** | — | Карточка схемы не показывается; только классический путь |

| Сущность | Смысл |
|----------|--------|
| **Точка** | `space_plan_id?` — ссылка на published схему |
| **Bind** | `(point_id, node_id)` → `service_id` + опц. `staff_id` · **не** в JSON геометрии |
| **Услуга** | Источник **цены** и длительности; ценник на схеме = цена услуги |
| **Запись** | Как сейчас; опц. метаданные места (node/emoji) в комментарии / later `space_node_id` |

Один аккаунт: хозяин настраивает bind на **своей** точке; как клиент ходит к другим — чужой guest flow.

## 3. Жизненный цикл

### A. Слой хозяина (bind)

| Фаза | Как |
|------|-----|
| **Создать геометрию** | Ресурсы → Схемы → Publish ([space-plan-resources.md](space-plan-resources.md)) |
| **Подключить** | Точка → выбрать `space_plan` |
| **Активировать витрину** | Хотя бы один emoji `bookable` с bind на активную услугу |
| **Действовать** | Тап emoji / bulk «всем одинаковым» → услуга / услуга+мастер |
| **Учитывать** | Ценник всегда из услуги; смена цены услуги обновляет витрину |
| **Отвязать** | Снять bind с node; или сменить/снять схему с точки |
| **Архив схемы** | Старые bind читают last published, пока не заменят план |
| **Отклонить** | Decor-emoji и фигуры без `bookable` — bind запрещён |

### B. Слой гостя (запись)

| Фаза | Как |
|------|-----|
| **Войти** | Чужой профиль → «Записаться» → экран записи к хозяину |
| **Выбрать место (путь А)** | Карточка «Схема» → тап bookable-emoji → «Продолжить» → услуга+мастер подставлены |
| **Или услуга (путь B)** | Селектор услуги → мастер (как сейчас); схему можно не открывать |
| **Дата / слот** | Расписание хозяина; слоты мастера |
| **Подтвердить** | Одна CTA «Записаться» в теле формы → запись **сразу confirmed** |
| **Учитывать** | Inbox хозяина / «Мои бронирования» — как [booking.md](booking.md) |
| **Отменить** | Правила отмены записи без изменений схемы |

Нет тупика: без bind на выбранном emoji — «Продолжить» недоступен / подсказка; гость уходит в путь B.

## 4. Карта экранов

### Хозяин

| Экран | Платформа |
|-------|-----------|
| Точка → «Схема и ценники» | Mobile + web |
| Bind: план слева + панель услуги/мастера | **Web** основной · mobile — сетка групп |
| Create/edit точки → поле схемы | Mobile + web |

Web: `/app/settings/booking/p/{pointId}/visual`  
Входы: обзор точки · Услуги → баннер · nav «Схема».

### Гость

| Экран | Где |
|-------|-----|
| `BookingClientPage` | Услуга / мастер / дата / слот + карточка схемы |
| `BookingSpacePlanGuestMockPage` | Fullscreen схема → выбор места → назад с подстановкой |

Шаги на экране записи (если схема включена):

```
1. Схема (опц.) → 2. Услуга → 3. Мастер → 4. Дата → 5. Слот → Записаться
```

После выбора места шаги 2–3 уже заполнены; скролл к дате.

## 5. Стыки → решения

| Тема | Решение |
|------|---------|
| Цена на emoji | **Только** из услуги; на emoji не храним свою цену |
| Что кликабельно | Только emoji с `role: bookable` + есть bind |
| Decor / стены / text | Видны, без ценника и без тапа для записи |
| Режим bind A | Только услуга → мастер выбирается на экране записи (если >1) |
| Режим bind B | Услуга + мастер сразу |
| Bulk «одинаковые emoji» | По **глифу** emoji; у каждого node свой ряд bind |
| `groupId` в редакторе | Визуальная связка мест; гость выбирает **одно** место (unit primary) |
| Сколько мест за раз | **Одно** место → одна запись (v1) |
| Место vs слот | Место задаёт услугу/мастера; **занятость** = слоты мастера, не «кресло taken» |
| Схема без bind | Карточка есть; тап без bind не ведёт к записи |
| Нет схемы на точке | Карточки схемы нет; только классика |
| Запись к себе | Запрещена (как в booking.md) |
| Бронь (venue) | Другой сервис; те же emoji-правила можно переиспользовать позже |
| Кнопка «Записаться» | Одна CTA в теле формы (не дубль у «назад») |
| Mock без бэка | Локальные слоты + demo-каталог; confirm не блокируется ошибкой API |

## 6. Сеть / sync / сессии

| Что | Правило |
|-----|---------|
| Геометрия | Read-only published `space_plan` |
| Bind | Правда на точке; mock: prefs / memory / localStorage |
| Слоты | Online (prod); mock — локальная сетка дня |
| Создать запись | Online; mock success если бэк отклонил |
| Offline | Просмотр схемы из кэша ок; confirm — нет |
| Logout | Wipe mock binds / guest showcase ключей user |

## 7. Уведомления

Как у обычной записи ([booking.md](booking.md) / feed):

| Событие | Канал |
|---------|-------|
| Гость записался | Inbox хозяина + notif клиенту «вы записаны» |
| Отмена / перенос | Как сейчас |
| Publish схемы / новый bind | Без отдельного push |

Текст notif **не обязан** содержать emoji места в v1; место может жить в заметке записи.

## 8. Вне скоупа (v1)

- Бэк-таблица bind / колонка `space_node_id` на booking (очередь SPEC)  
- Мультивыбор кресел одной записью  
- «Кресло занято» независимо от календаря мастера  
- Оплата / депозит за место  
- Рисование схемы на мобилке  
- Смешение inbox с сервисом Бронь  
- Ценники на rect/ellipse

## 9. Мозаика слоёв

```
Ресурсы: geometry (emoji bookable | decor)
    ↓ space_plan_id
Точка Записи
    ↓ binds: node_id → service_id (+ staff_id?)
Гость: тап места → услуга/мастер → дата/слот → create_booking
```

| Слой | Где пишет |
|------|-----------|
| Геометрия | Только сайт / Ресурсы |
| `space_plan_id` на точке | Хозяин mobile+web |
| Bind emoji | Хозяин (web основной) |
| Цена | Услуга |
| Слот / запись | Как booking.md |

---

## 10. Happy path (мок / prod)

```
Хозяин (сайт)
  1. Ресурсы → Схемы → нарисовать / AI → Publish
  2. Запись → точка → прикрепить схему
  3. «Схема и ценники» → emoji → услуга + мастер

Гость (мобилка)
  4. Профиль хозяина → Записаться
  5. Открыть схему → тап кресло → Продолжить
  6. Дата (уже выбран слот в mock) → Записаться
  7. Toast «Запись подтверждена» → назад
```

Альтернатива: шаг 5 пропустить → выбрать услугу вручную.
