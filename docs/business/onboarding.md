# Онбординг

**Статус:** **v2 в приложении** (ветки лента / бизнес / оба) · **v3 каркас** умных service-tips · v1 — история  
**Для кого:** продукт / бизнес / маркетинг  
**Не про:** анимации, cubit internals  
**Макет:** canvas `clover-tutorial-pilot`  
**Правило агента:** [`.cursor/rules/clover-onboarding.mdc`](../../.cursor/rules/clover-onboarding.mdc)

---

## Цель

После входа быстро и по-человечески показать, **зачем Clover** и что у бренда есть — без сравнений с чужими приложениями.

Дальше — **умные tips**: при появлении/включении сервиса коротко объяснить его, опираясь на **кэш прогресса** и **контекст** (теги, первый вход в хаб), без спама.

Онбординг не регистрирует и не проверяет личность — это уже [аутентификация](authentication.md).

---

## Когда показывается

| Когда | Что происходит |
|-------|----------------|
| Первый вход (ещё не проходил стартовый тур) | После успешного входа → онбординг **v2** |
| Повторный вход / уже видел `app_v2` | Сразу на **главный экран** |
| Из настроек | О приложении → **посмотреть снова** (replay; флаг «видел» не сбрасывается) |
| Позже: первый вход в сервис / после супер-тега | **Service tip** (разово), если ещё не `seen` и проходит гейт |

В любой момент — **Пропустить** (стартовый тур и tip).

## v1 (история)

Один общий поток из 6 слайдов. Больше не показывается новым пользователям (`app_v1`).

## v2 (в приложении) — два сюжета + «оба»

Человек **сам выбирает тон тура** на первом экране (не анкета ролей, а сюжет):

| Путь | Для кого | Длина | Смысл |
|------|----------|-------|--------|
| **Лента** | Обычный пользователь | 6 слайдов | Что происходит → места → запись и бонусы → чат → фильтры → Clover с тобой |
| **Бизнес и предприятия** | Предприниматели, точки | 5 слайдов | Витрина → супер-теги → сервисы → клиент находит тебя |
| **И лента, и дело** | Оба | 5 слайдов | Для себя + для дела; маленький старт |

### Супер-теги в туре (человечески)

- **Обычный тег** — описывает (кто / тип / место).  
- **Супер-тег** — включает кнопку и сервис (Запись, Посещаемость, Ресурсы).  
- Нет тега → нет силы. Выбор в **Редактировать профиль**.  
Подробнее: [tag-powers.md](tag-powers.md).

### Карта прохождения v2

```
Вход
  → «Кто ты в Clover?»
       ├─ Лента (6) ────────────┐
       ├─ Бизнес (5) ───────────┼→ Домой
       └─ Оба (5) ──────────────┘
  (Skip в любой момент)

Replay: Настройки → О приложении → тот же выбор путей
```

### Тексты слайдов v2

Источник в коде: `OnboardingCatalog` (feed / business / both). Краткая логика:

**Лента:** что происходит → места рядом → запись и бонусы → поделись с близкими → фильтры → Clover с тобой.  
**Бизнес:** витрина → супер-теги → сервисы → клиент находит тебя.  
**Оба:** для себя + для дела → маленький старт.  

Тон: абстрактно, коротко, мягко. Без сравнений с чужими брендами. Без лишних деталей.

## v3 — умные service-tips (каркас)

Стартовый тур **не раздуваем** каждым новым сервисом. Новая фича → **отдельный tip** с EN-ключом, текстом на клиенте и правилом «когда показать».

### Модель

| Поле | Смысл |
|------|--------|
| `id` | EN ключ (`service_booking`, `service_attendance`, …) — в кэше `seen` |
| `service_key` | Домен: `booking` / `attendance` / `resources` / `map` / … |
| `surface` | Где триггерим: `booking_hub`, `attendance_hub`, `resources_hub`, `map_first_open`, … |
| `required_tag` | Опционально супер-тег (`booking`, `attendance`, …); без тега — не показываем |
| `slides` | 1–3 коротких слайда (тот же тон, что v2) |
| `priority` | Если несколько unseen — меньшее число раньше |

### Кэш прогресса

| Что | Где |
|-----|-----|
| Seen tip ids | `OnboardingStore` per `userId` (диск; переживает logout на устройстве, аккаунты не мешают) |
| Стартовый тур | tip id `app_v2` |
| Service tips | свои id; `markSeen` после skip/complete |

**Правило:** UI сначала читает кэш `seen` → не мигает повторно. Сеть для tips **не** нужна.

### Когда показывать (логика)

```
Открыли surface (хаб сервиса / первый раз feature)
  → Resolver: candidates для surface
  → отфильтровать already seen
  → отфильтровать по required_tag (теги профиля из уже загруженного snapshot)
  → взять с min priority
  → показать tip UI (sheet / mini-page — решение экрана)
  → Skip или Done → markSeen
```

Не участник сервиса (нет тега / нет входа в хаб) — tip **не** крутим «на всякий».

### Добавление новой фичи в онбординг

1. Продукт: 1–3 фразы в этом файле или в доке сервиса (ссылка сюда).  
2. `OnboardingTipId` + запись в `OnboardingTipCatalog`.  
3. В хабе/экране сервиса: один вызов resolver при первом показе surface.  
4. Не тащить новый сервис в слайды v2 без явного продукта.

### Заготовки tips (тексты можно уточнять)

| id | surface | tag | Смысл одной фразой |
|----|---------|-----|-------------------|
| `service_booking` | `booking_hub` | `booking` | Запись: услуги, inbox, клиент с профиля |
| `service_attendance` | `attendance_hub` | `attendance` | Посещаемость: компании и смены |
| `service_resources` | `resources_hub` | `resources` | Ресурсы: места и фильтры витрины |
| `tip_map_events_toggle` | `map_first_open` | — | Лента ↔ карта двойным тапом Home |

UI показа tips — подключается по мере экранов; **контракт id/кэш/гейты уже есть**.

## Кто участвует

| Роль | Что делает |
|------|------------|
| Пользователь | Выбирает сюжет (v2), листает, пропускает; позже — видит tip сервиса разово |
| Clover | Тур + кэш seen + resolver |
| Продукт | Тексты слайдов и tips |

---

## Результат

После стартового тура человек понимает хотя бы:

- Clover = город + (по желанию) дело в одном аккаунте;  
- лента / карта / чат / профиль;  
- супер-теги включают сервисы;  
- на старте достаточно малого шага.

После service tip — зачем этот хаб, без перечитывания всего тура.

---

## Что пока не входит

| Тема | Статус |
|------|--------|
| Полноценный tip-UI на каждом хабе | Каркас resolver/catalog; wire по экранам — по «делай» |
| Онбординг до входа | Нет |
| Онбординг-слайды на вебе | Вне приоритета сайта |
| Серверный sync seen между устройствами | Позже; сейчас per-device cache |
