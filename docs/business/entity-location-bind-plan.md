# План: компания / точка только с местоположением

**Статус:** план (закреплено продуктом) · **разработка не начата**  
**Связано с:** [locations.md](locations.md), [booking-points.md](booking-points.md), [attendance.md](attendance.md), [resources-guide.md](resources-guide.md)

## Решение (закреплено)

Сущности **компании** создаются в двух сервисах:

| Сервис | Сущность | Сейчас |
|--------|----------|--------|
| **Запись** (`booking`) | Точка (`booking_points`) | Создаётся без обязательного места |
| **Посещаемость** (`attendance`) | Компания / workplace | Создаётся без обязательного места |

**Новое правило:** компанию / точку **нельзя создать**, пока не прикрепишь её к **местоположению** из Ресурсов (`locations`).

Цель — не оставлять пустой адрес: витрина, карта, геозона и (позже) отзывы всегда опираются на место.

### Фильтр постов по местоположению (тоже план)

Рядом с текущими фильтрами постов — **иконка / параметр фильтра по `location`**:

- Посты, у которых есть привязка к местоположению из Ресурсов, можно сузить по выбранному месту (или «все места»).
- Точка входа: тот же паттерн, что у фильтров ленты / витрины — **иконка фильтра**, не отдельный сервис.
- Это **не** фильтр города ленты (страна/город справочника) и **не** категории витрины профиля — отдельное измерение: сохранённое место автора.

**UI (mock/partial):** на профиле рядом с tune-фильтром Ресурсов — иконка места; выбор из своих locations; фильтр сетки на клиенте. RPC `p_location_id` — позже.  
Детали UX на чужом профиле — позже (сейчас sheet: только свой профиль).

## Правила

1. **Создать** точку записи или компанию посещаемости → обязательный выбор / создание `location_id`.
2. Местоположения по-прежнему живут в **Ресурсы → Местоположения** ([locations.md](locations.md)).
3. В флоу создания сущности: выбрать существующее место **или** создать новое место и сразу привязать (без отдельного «сначала сходи в Ресурсы» как единственного пути — но место как сущность обязательно).
4. **Удалить место**, на которое ссылается точка / компания → **нельзя**. Сначала перенести сущность на другое место (или отвязать, если продукт позже разрешит — сейчас отвязка без замены **не** планируется).
5. Без ссылок → место удалять можно (как сейчас для постов: неактивное / удаление по RLS владельца — уточнить при реализации).
