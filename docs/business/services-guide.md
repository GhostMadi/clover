# Гайд сервисов

**Статус:** актуально  
**Связано с:** [settings.md](settings.md), [booking.md](booking.md), [attendance.md](attendance.md), [resources-guide.md](resources-guide.md), [tag-powers.md](tag-powers.md)

---

## Зачем

Один вход **Настройки → Гайд**: понятно разжёванные шаги по сервисам (Запись, Посещаемость, Ресурсы) и кнопка **Активировать**, если admin-тега ещё нет.

---

## Точка входа

| Откуда | Куда |
|--------|------|
| Настройки → **Гайд** | Хаб карточек сервисов |
| Карточка сервиса | Экран гайда (`booking` / `attendance` / `resources`) |

---

## Карточки хаба

| Ключ | Заголовок | Admin-тег |
|------|----------|-----------|
| `booking` | Запись | `booking` |
| `attendance` | Посещаемость | `attendance` |
| `resources` | Ресурсы | `resources` |

Бейдж на карточке: **Активировать** / **Активно** по тегу профиля.

---

## Активировать

На экране гайда:

| Состояние | Кнопка |
|-----------|--------|
| Нет admin-тега | **Активировать …** — добавляет тег к уже выбранным (остальные не снимает) |
| Тег уже есть | **Открыть …** — хаб сервиса в настройках |

После активации обновляется `ProfileCubit`, на профиле появляются ярлыки силы.

Worker-теги (`bookingCalendar`, `attendanceWork`) гайдом не вешаются — только admin.

---

## Содержание (смысл шагов)

### `booking`

Включить → услуги → заявки / inbox → бонусы на услуге → команда.

### `attendance`

Включить → компания и геозона → пригласить людей → табель.

### `resources`

Включить → местоположения → фильтры витрины.

Тексты — на клиенте, мягко и ясно ([services_guide_catalog.dart](../../lib/feature/_settings_/settings_guide/data/services_guide_catalog.dart)).

---

## Правила

- Ключи EN; подписи на фронте.  
- Активация = тот же контур тегов, что edit profile (`profile_tag_links`).  
- RLS / RPC по-прежнему решают права на действия сервиса.  
- Мобилка и сайт — один смысл.

## Вне скоупа

- Гайд по бонусам / брони зала как отдельный сервис в этом хабе.  
- Активация worker-тегов из гайда.
