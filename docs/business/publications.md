# Публикации (как сейчас)

**Статус:** актуально на сейчас  
**Для кого:** продукт / бизнес / дизайн  
**Не про:** API, RPC, storage buckets

---

## Цель

Публикация — основной контент в Clover: фото, текст, реакции, комментарии.

**Ивент** — не отдельный «тип сущности для пользователя», а **публикация с точкой на карте и периодом времени** (до 24 часов).

Вкладка **Event** — городская лента (по умолчанию **все** посты города).  
Вкладка **Map** — **только ивенты** на карте. Это два разных среза, не «одно и то же в другом виде».

---

## Кто участвует

| Роль | Что делает |
|------|------------|
| Автор | Создаёт публикацию / ивент, архивирует, удаляет, кладёт в коллекцию |
| Зритель | Смотрит, реагирует, комментирует, сохраняет, делится в чат |
| Clover | Показывает контент в ленте, на карте, в профиле |

---

## Что такое публикация

Для пользователя это карточка:

- фото (сейчас до 15 кадров);
- заголовок и описание;
- эмодзи, теги (по желанию);
- место (по желанию);
- реакции, комментарии, сохранение, шаринг в чаты Clover.

Два режима при создании (один поток «Новая публикация»):

| Режим | Условие | Результат |
|-------|---------|-----------|
| **Обычная публикация** | Период события **не** задан | Пост → витрина профиля и городская лента (фильтр «Все») |
| **Ивент** | Задан **период события** | Маркер на карте **+** пост → карта, лента (и «Ивенты», и «Все»), профиль |

---

## Как устроено (для продукта)

«Публикация» и «ивент» — **не два типа сущности**. Корень всегда **пост**; ивент — тот же пост, если к нему привязаны место и период.

| Связь | Смысл |
|-------|--------|
| Пост без маркера | Обычная публикация |
| Пост + маркер (место + период) | Ивент |
| Пост + услуга записи | Витрина процедуры: гость может записаться **на эту услугу** — тот же flow, что с профиля, услуга уже выбрана. См. [booking.md](booking.md) |
| Пост + бронь мест | Витрина зала/стола: гость может **запросить бронь** с поста — заведение (и опц. сеанс) уже выбраны. См. [venue-seating.md](venue-seating.md) |
| Пост + кластер | Коллекция на витрине профиля. См. [clusters.md](clusters.md) |

Будущие расширения (опрос и т.п.) — по тому же правилу: опциональная связь на посте, без отдельного «типа публикации».

---

## Связь с ивентом

Это ключевое правило продукта:

```
Обычная публикация  =  пост без маркера
Ивент               =  пост + маркер (место + период до 24 ч)
```

| Вопрос | Как сейчас |
|--------|------------|
| Пост без ивента? | Да — обычная публикация на профиле |
| Ивент без поста? | В нормальном создании **нет**: всегда создаётся пара маркер + пост. Голый маркер на карте без поста — крайний случай («у маркера нет поста») |
| Один пост — сколько маркеров? | Максимум **один** |
| Один маркер — сколько постов? | В модели может быть несколько; в UI создания сейчас всегда **один** пост вместе с маркером. Отдельного «добавить ещё пост к уже живому ивенту» нет |
| Что открывает карта? | Точку (маркер) → шторка с **главным** постом ивента |
| Архив | Пост / ивент → общий архив **публикаций** (маркер у ивента тоже) |

### Именование (чтобы не путаться)

| В UI | Смысл |
|------|--------|
| Вкладка **Event** | Лента города («что происходит») |
| Вкладка **Map** | Карта маркеров |
| **Ивент / событие** | Маркер + связанный пост(ы), период времени |
| **Маркер** | Точка на карте; «тело» контента — в посте |
| Фильтр ленты **Ивенты / Все** | Только с маркером vs все посты города. **По умолчанию — «Все»** |

Онбординг говорит то же: лента и карта, «ставь маркер, публикуй пост».

## Создание

**Откуда:** свой профиль → **+** → публикация.  
Отдельного потока «создать маркер» нет.

**Шаги:**

1. Выбрать фото.
2. При необходимости подрезать / подготовить кадры.
3. Заполнить карточку публикации:
   - заголовок, описание;
   - фильтры / категории для поиска (если есть);
   - эмодзи, теги;
   - место из сохранённых локаций;
   - **период события** (необязательно) — включает режим ивента;
   - **услуга для записи** (необязательно) — только если у автора тег `booking` и есть активные услуги;
   - **заведение для брони мест** (необязательно) — только если у автора тег `venue` и есть заведение; опционально сеанс. См. [venue-seating.md](venue-seating.md).
4. Опубликовать → прогресс на профиле → пост в сетке; обычный пост — ещё в ленте «Все»; если ивент — ещё на карте и в ленте при любом фильтре.

**Если это ивент (период задан), обязательно:** эмодзи, место с координатами, длительность от 1 минуты до **24 часов**.  
**Если обычная публикация:** достаточно медиа; остальное — по желанию.

## Где появляется

| Место | Что видно |
|-------|-----------|
| **Event** (лента) | По умолчанию **«Все»** (обычные посты и ивенты города); фильтр **«Ивенты»** — только с маркером. Ещё фильтры: место, даты, эмодзи, теги |
| **Map** | Только маркеры (ивенты); тап → главный пост. Обычные посты на карте **не** появляются |
| **Профиль** | Сетка всех живых постов (с маркером и без); фильтр по кластеру |
| **Кластеры** | Коллекции на витрине; пост может быть в одном кластере или ни в каком |
| **Чат** | Поделиться постом → получатели из **подписок** → превью в DM. См. [chats.md](chats.md) |
| **Сохранённые** | Настройки → сохранённые посты |
| **Архивы** | Отдельно: публикации / ивенты / кластеры |

Счётчик «Публикации» в шапке профиля — живые (не удалённые, не в архиве поста).

## Видимость (бизнес-уровень)

| Правило | Эффект |
|---------|--------|
| Живой публичный контент | Не удалён, пост не в архиве; у ивента маркер тоже не в архиве |
| Архив поста | Не в лентах и сетке; в «Архивы → Публикации» |
| Архив маркера | Не на карте и не в ленте ивентов; в «Архивы → Ивенты» |
| Сон аккаунта (hibernate) | Контент автора скрывается из городских лент |
| Время ивента | upcoming / active / finished (+ cancelled); на карте обычно upcoming + active |
| Длительность ивента | не больше 24 часов |

Отдельного режима «только для подписчиков» у поста сейчас нет.

## Медиа

- Сейчас в продукте — **фото**.
- Видео в модели может быть заложено, но в клиенте не создаётся и не показывается как основной сценарий.
- Обложка в сетке / на карте — основное (обычно первое) фото.

## Кластеры и публикации

Подробный процесс: [clusters.md](clusters.md).

- Кластер = коллекция на профиле (создаётся отдельно с **+**).
- Пост можно положить в кластер или оставить без коллекции.
- На профиле полоска кластеров фильтрует сетку.
- Ивент-посты тоже могут лежать в кластере — витрина не отрезает посты с маркером.

## Услуга записи на посте

Если у автора тег **`booking`**, при создании можно привязать **одну активную услугу**.

| Кто | Что видит |
|------|-----------|
| Гость | Блок услуги + **«Записаться на эту услугу»** — тот же flow записи, услуга уже выбрана |
| Автор своего поста | Услугу (если привязана) **без** кнопки записи — к себе нельзя |
| Услуга снята / неактивна | CTA нет, пост остаётся |

Сменить или снять услугу **после** публикации отдельным сценарием **не нужно**: пост — снимок витрины; другая услуга → новый пост; неактивная услуга → CTA сама пропадает. Решение и кейс: [booking.md](booking.md#кейс-смена-услуги-у-уже-опубликованного-поста--зачем-был-и-почему-нет).

---

## Бронь мест на посте

Если у автора тег **`venue`**, при создании можно привязать **одно заведение** (и опционально **сеанс**).

| Кто | Что видит |
|-----|-----------|
| Гость | Блок заведения (+ сеанс, если есть) + **«Забронировать место»** — тот же flow брони мест; дальше **запрос**, не auto-confirm. См. [venue-seating.md](venue-seating.md) |
| Автор своего поста | Превью привязки **без** кнопки брони |
| Заведение снято / витрина недоступна | CTA нет, пост остаётся |

Смена заведения/сеанса после публикации — **не делаем** (тот же принцип, что у услуги записи).  
На одном посте допустимы и услуга записи, и бронь мест (два CTA), если у автора оба тега.

---

## Пока не в этом процессе / слабо

- UX «добавить второй пост к уже существующему ивенту»;
- видео как основной формат;
- создание поста не с профиля (отдельная FAB на Home);
- шаринг наружу (ссылка / Stories) — только чаты Clover;
- полноценное редактирование уже опубликованного как основной сценарий;
- приватность поста по аудитории.

## Коротко одной схемой

```
Профиль → + → Новая публикация
    ├── без периода  →  пост              → профиль + лента «Все»
    └── с периодом   →  маркер + пост     → карта + лента + профиль

Event (вкладка) = лента города, по умолчанию «Все»
Map (вкладка)   = только ивенты → главный пост

пост ──(0..1)──► маркер     = ивент, если маркер есть
маркер ──(1..N)──► посты    (модель; создание UI = 1 пост)
пост ──(0..1)──► кластер
пост ──(0..1)──► услуга записи  (гость → тот же flow)
пост ──(0..1)──► заведение брони мест (+ опц. сеанс)  (гость → запрос брони)
```
