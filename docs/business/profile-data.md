## Правило (запомнить)

Справочники профиля (страна, город, теги, статусы-коды):

- на **бэке** — только **английские ключи** (массив/набор слов-slug);
- **переводов на бэке нет**;
- на **фронте** — это **enum’ы**, подписи (RU и др.) только в приложении.

Свободный текст пользователя (`full_name`, `bio`, `username`, …) — не справочник: хранится как ввёл человек.

## 1. Идентификация и контакты

| Поле (БД) | Тип | Что это | Примечание |
|-----------|-----|---------|------------|
| `id` | UUID (текст в приложении) | ID пользователя = `auth.users.id` | Обязательно, первичный ключ |
| `email` | текст | Email | Может быть пустым; на edit — только чтение |
| `phone` | текст | Телефон | Зеркало из auth (E.164-подобная строка); может быть пустым |
| `full_name` | текст | Отображаемое имя | Свободный текст |
| `username` | текст | Ник `@…` | Свободный текст + лимит смен |
| `username_change_count` | целое число | Сколько раз меняли ник | Служебное |
| `username_next_change_allowed_at` | дата/время | Когда снова можно менять ник | Служебное |

## 3. Локация — **коды** (не произвольные названия в БД)

В БД хранятся **английские slug-коды**. Перевод («Алматы», «Казахстан») — **только на фронте** в enum. Бэк переводов не хранит.

| Поле (БД) | Тип в БД | Тип в приложении | Примеры значений |
|-----------|----------|------------------|------------------|
| `country_code` | текст | enum `CountryCode` | `kz`, `ru` |
| `city_code` | текст | enum `CityCode` (вместе со страной) | `almaty`, `astana`, `moscow`, … |

**`CountryCode` (сейчас в приложении):**

| Код | Подпись |
|-----|---------|
| `kz` | Казахстан |
| `ru` | Россия |

**`CityCode` (сейчас в приложении):**

| Страна | Код города | Подпись |
|--------|------------|---------|
| `kz` | `almaty` | Алматы |
| `kz` | `astana` | Астана |
| `kz` | `shymkent` | Шымкент |
| `ru` | `kazan` | Казань |
| `ru` | `moscow` | Москва |
| `ru` | `saintPetersburg` | Санкт-Петербург |

Если в БД есть код города, которого нет в enum — приложение показывает сырой slug.

## 4. Теги — единый справочник (`marker_tags`)

Профиль, маркеры, фильтры — **один** список тегов. В БД ключи EN в `marker_tags.key`, группы в `group_key`. Перевод — enum `MarkerTagKey` + `MarkerTagGroupKey` на фронте.

| Поле / связь | Тип | Что это |
|--------------|-----|---------|
| `tag_link_id` | UUID или пусто | Ссылка на набор тегов (`profile_tag_links`) |
| `tag_ids` (из связи / view) | список UUID | Id строк справочника `marker_tags` |
| теги в UI | список моделей + enum | `salon`, `business`, `booking`, … |

**Группы (`group_key`):**

| Группа | Примеры | Где |
|--------|---------|-----|
| `who` | business, individual, brand | профиль, маркер |
| `type` | salon, barbershop, music, sports, food, tech, store | профиль (бывшие categories) |
| `for` | kids, womenOnly, … | профиль, маркер |
| `place` | restaurant, cafe, beauty, … | маркер, фильтр |
| `event` | workshop, concert, … | маркер, фильтр |
| `format` | indoor, online, … | маркер, фильтр |
| `conditions` | free, paid, … | маркер, фильтр |
| `admin` | booking | мажорные силы хозяина (нижняя линия профиля) |
| `worker` | bookingCalendar | доп. функции исполнителя (верхняя линия) |

Тег **`booking`** (`MarkerTagGroupKey.admin`) — «принимаю запись» → на чужом профиле кнопка «Записаться»; на своём — нижняя линия → inbox.  
Тег **`bookingCalendar`** (`MarkerTagGroupKey.worker`) — «календарь заказов» → верхняя линия.  
Определения **admin / worker**: [tag-powers.md](tag-powers.md) · ТЗ: [booking-tz.md](booking-tz.md).

~~`account`~~ как group_key для сил **снят** → вместо него `admin` / `worker`.

## 7. Флаги и статусы — **enum / bool**

| Поле (БД) | Тип | Значения | Смысл |
|-----------|-----|----------|--------|
| `has_filters` | bool | — | Есть ли сохранённые фильтры витрины |
| `account_state` | текст с ограничением | `active` \| `hibernate` | Аккаунт обычный или «сон» (контент скрывается) |
| `content_visible` | bool | (служебное к состоянию аккаунта) | Видимость контента при сне / пробуждении |

**`account_state`:** `active`, `hibernate`  
(есть в БД и в бизнес-правилах видимости; в `ProfileNewModel` на клиенте сейчас **не** прокинут как поле модели — но в таблице лежит).

## 9. Как это читает приложение (группы)

| Группа | Примеры полей | Характер данных |
|--------|---------------|-----------------|
| Свободный текст | `full_name`, `username`, `bio`, `email`, `phone` | Строка |
| URL | `avatar_url`, `background_url` | Строка-ссылка |
| Коды справочников | `country_code`, `city_code` | Enum / slug |
| Теги | `tag_link_id` → `tag_ids` / `MarkerTagKey` | Id + ключи-enum |
| Числа | счётчики, `username_change_count` | int |
| Статусы | `account_state` | Enum |
| Флаги | `has_filters`, `content_visible` | bool |
| Время | `created_at`, `updated_at`, лимиты ника | datetime |

---

## 10. Чего в строке профиля **нет** (живёт рядом)

Не колонки `profiles`, а отдельные сущности / экраны:

- посты и медиа;
- кластеры;
- бронирования и услуги;
- баланс бонусов клиента;
- чаты;
- настройки темы/языка.

---

## Коротко

Профиль = **идентичность + витрина + коды места/категории + теги + счётчики + статусы**.  
Свободный текст — имя, ник, био, контакты, URL картинок.  
Всё «справочное» — **коды** (`kz`, `almaty`, `beauty`, `booking`, `active`/`inactive`, …), не произвольные длинные названия в этих колонках.
