# План: отзывы по точкам записи

**Статус:** план реализации (закреплено продуктом) · прод-бэк ещё не начат · mock UI есть  
**Связано с:** [booking.md](booking.md), [booking-points.md](booking-points.md), [tag-powers.md](tag-powers.md), [entity-location-bind-plan.md](entity-location-bind-plan.md)

Ранее в [booking.md](booking.md): отзывы в приложении **не делали**. Ниже — актуальный контракт.

---

## Объект отзыва

| | |
|--|--|
| **Куда пишется** | На **точку записи** (`booking_points`), не на аккаунт человека и не на «рейтинг адреса» из Ресурсов |
| **Место** | У точки — `location` ([entity-location-bind-plan.md](entity-location-bind-plan.md)); FK отзыва = `point_id` |
| **На профиле хозяина** | Сводка ★ + N по его точкам (если тег `feedback`) |

Не оцениваем соц-аккаунт и не вешаем звёзды на attendance.

---

## Видимость на витрине = супер-тег `feedback`

Как [tag-powers.md](tag-powers.md): **нет тега → нет блока**. Отдельного toggle нет.

| Условие | Профиль |
|---------|---------|
| Нет `feedback` | Полоски нет |
| Есть `feedback` | Сводка ★; тап → список + ответы хозяина |

Ключ: `feedback` · `admin` · цвет сервиса Запись. Миграция: `20260922120000_feedback_marker_tag.sql`.

---

## Кто может оставить отзыв (закреплено)

**Писать могут все** — отдельных блокировок / гейта «только после Оказана» **нет**.

| Правило | Как |
|---------|-----|
| Кто | Любой авторизованный пользователь |
| Куда | На точку (`point_id`) |
| Форма | ★ **1–5** обязательно; текст опционален |
| Лимит v1 | Один отзыв автора на точку (правка / удаление своего — при реализации) |

CTA из «Мои записи» после визита — удобный вход, **не** обязательное условие.

---

## Ответ хозяина (закреплено)

| Делаем | Не делаем |
|--------|-----------|
| **Один ответ** на отзыв от имени точки (создать / изменить / удалить) | Ветки «как комменты» (reply на reply, дерево) |
| Ответ виден под отзывом в списке | Отдельный чат / тред дискуссии |

---

## Что сознательно не делаем

- Оценка аккаунта / постов / чатов  
- Отзывы на workplace посещаемости  
- Накрутка, бонусы за отзыв, «модерация как у агрегаторов»  
- Toggle «скрыть отзывы» (только тег `feedback`)  
- Цепочки комментариев под ответом

## Что видит клиент / гость

### Профиль host (если `feedback`)

1. Аватар · имя · статистика  
2. Био / город  
3. **★ среднее · N отзывов** → шторка списка + фильтр по точке + ответ хозяина  
4. Записаться / подписка  
5. Кластеры · посты  

### Точка

★ этой точки + список отзывов (+ ответ).

Mock: `PointReviewsMock.enabled` + `hasFeedbackTag`. Перед продом выключить.

## План реализации (очередь)

Порядок жёсткий: продукт (этот файл) → SPEC → миграция → mobile + web.

### Фаза A — контракт и бэк

1. Снять в [booking.md](booking.md) формулировку «отзывы не делаем»; ссылка сюда.  
2. SPEC в `docs/supabase/` + строка в `MIGRATIONS_INDEX.md`.  
3. Таблица отзывов: `point_id`, автор, stars, text, timestamps; уникальность автора×точки (v1).  
4. Ответ хозяина: поле/строка ответа (один на отзыв), RLS — писать ответ только host точки.  
5. RLS: читать публично (или по правилам витрины); писать — любой authenticated; без гейта completed.  
6. Агрегаты: средний ★ + count по точке / по host (RPC или view).

### Фаза B — витрина и точка (mobile + web)

7. Сводка на профиле только при теге `feedback` (как mock сейчас).  
8. Список отзывов + фильтр по точке + ответ хозяина.  
9. Форма «оставить отзыв» (выбор точки / с карточки точки).

### Фаза C — удобные входы (не гейты)

10. CTA «Оценить» в **Мои записи** (после визита — удобство).  
11. Мягкий in-app / пуш после «Оказана» — опционально позже.  
12. `point_id` на `bookings` — чтобы CTA сразу знал точку ([booking-points.md](booking-points.md) «сознательно позже»).

### Фаза D — дожим

13. Жалоба на отзыв (простая) — после живого потока.  
14. RPC-фильтр постов по `location_id` — отдельно ([entity-location-bind-plan.md](entity-location-bind-plan.md)).
